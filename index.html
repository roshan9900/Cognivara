Six phases. One evolving system.

Each phase builds on the last. You ship real, working components incrementally instead of only learning concepts in isolation — by week 16 they come together into one capstone system you defend live.

Phase 1Weeks 1–3

Engineering Foundations

Master production Python, asynchronous I/O, and transformer primitives required for low-latency LLM systems.

  • Week 1 — FastAPI & Async Python: async/await, Pydantic schemas, streaming responses, server-sent events (SSE) and non-blocking LLM calls.
  • Week 2 — Embeddings & Chunking: tokenization, semantic chunking strategies, local LLMs and INT8/INT4 quantization.
  • Week 3 — Transformer Architecture: self-attention, KV cache, time-to-first-token (TTFT), speculative decoding and inference benchmarking.
FastAPIAsync PythonPydanticEmbeddingsKV Cache
Phase 2Weeks 4–7

Production RAG Systems

Build retrieval systems that are accurate, fast and measurable — not just functional.

  • Vector Search: FAISS to Qdrant migration, HNSW indexing, and payload metadata filtering.
  • Hybrid Search: Combining BM25 keyword search with dense retrieval + cross-encoder reranking.
  • Advanced Retrieval: RAG-Fusion, HyDE (Hypothetical Document Embeddings), multi-query, Reciprocal Rank Fusion (RRF).
  • Evaluation & Tracing: Automated RAGAS evaluation, LLM-as-judge, LangSmith tracing, and Phoenix observability.
QdrantFAISSHybrid BM25RAGASLangSmithReranking
Phase 3Weeks 8–10

Agents, Tools & Security

Architect stateful agent workflows with tool calling, standardized protocol integration, and zero-trust security.

  • Week 8 — LangGraph & Stateful Agents: graph-based workflows, conditional routing, cyclic graphs, memory and planning nodes.
  • Week 9 — Tool Calling & MCP: function schemas, Model Context Protocol (MCP) architecture, multi-agent coordination and Human-in-the-Loop review.
  • Week 10 — Security & Guardrails: prompt-injection defense, input/output validation and least-privilege tool access policies.
LangGraphTool CallingMCPHITL GateGuardrails

Fine-Tuning Engineering

Practical model adaptation: know precisely when to fine-tune instead of defaulting to prompting or RAG.

  • Dataset Engineering: Synthetic dataset construction and evaluating against overfitting.
  • Catastrophic Forgetting: Benchmarking validation drift against original model performance.
  • Serving Optimization: Model distillation, INT8/INT4 weight quantization, and deployment sizing.

Engineering Architecture Guide

RAG, prompting, fine-tuning or agents?

A core principle taught throughout the program: learn when to choose each architecture based on empirical evidence, cost, and latency — not default assumptions.

If your system needs... Use this approach Why it matters in production
Current information or citations RAG Hybrid BM25 + dense vector search grounds responses and prevents hallucinations without retraining.
A consistent output format Prompting & Schemas Pydantic schemas and structured function calling ensure reliable JSON without training overhead.
A specific style or behaviour Fine-Tuning Instruction tuning aligns open-weight models to domain-specific syntax, acronyms, and formatting.
Lower inference cost at scale Fine-Tuning & Distillation Distilling a massive model into an 8B quantized model drastically cuts token costs and latency.
External actions & tool execution Agents & Tools LangGraph and Model Context Protocol (MCP) enable multi-step actions with Human-in-the-Loop review.

Frequently asked questions

Do I need prior GenAI experience?

No. We build up from engineering foundations. However, Python proficiency and familiarity with basic SQL and REST APIs are required to keep pace with the hands-on labs.

What is the batch timing and weekly time commitment?

The program runs for 16 weeks (~160 total live hours) with live online sessions from 8:00 to 10:00 PM IST, Monday through Friday. Sessions are capped at 20 engineers for direct mentor attention.

What if I miss a live session?

Recordings and complete code repository materials are available for enrolled learners for every live session.

Will I fine-tune a real model?

Yes — you will apply QLoRA to a small open-weight model during Phase 4 (Fine-Tuning Engineering) and benchmark against catastrophic forgetting and inference serving trade-offs.

Do I need to pay for GPU or cloud usage?

We recommend budgeting roughly ₹2,000–5,000 externally for cloud/GPU resources (e.g., AWS EC2, Qdrant Cloud, Modal/RunPod) during the program, paid as used.

What is the program fee and are EMI plans available?

The program fee for the Founding Batch is a one-time payment of ₹49,999. EMI options are currently not available.

Can I use the capstone in my portfolio?

Yes. The capstone is specifically designed as an end-to-end, production-ready public GitHub project with architecture documentation, latency/cost metrics, and an evaluation report that you can showcase to employers and recruiters.

Is placement guaranteed?

No. We provide comprehensive career and placement assistance — 1:1 resume review, GitHub/portfolio polishing, technical mock interviews, and job-search strategy. This does not constitute a guarantee of employment, salary, company, or role.

Is there a certificate awarded?

Yes, awarded upon completing all program milestones and successfully defending your capstone project live.
